⚡ 시행착오 01. 단순한 온도 스위치를 폐루프 열 제어 시스템으로 재정의한 과정
📌 프로젝트의 최초 목표

이 프로젝트를 시작할 당시의 목표는 매우 단순했다.

NTC Thermistor의 온도가 50℃ 이상이 되면 팬을 작동시키고, 팬이 저항을 냉각하도록 한다.

처음에는 이를 단순히 “온도가 높아지면 스위치를 켜는 회로”라고 생각하였다. NTC Thermistor를 전압 분배 회로에 연결하고, 비교기를 이용해 특정 전압에 도달했을 때 모터를 켜면 프로젝트가 완성될 것으로 예상했다.

초기 구상은 다음과 같았다.

NTC 온도 상승
↓
NTC 저항 감소
↓
분압 전압 변화
↓
비교기 출력 전환
↓
팬 작동

그러나 이 구조만으로는 내가 원하는 시스템을 완전히 표현할 수 없었다.

팬이 켜지는 것은 확인할 수 있지만, 팬이 실제로 온도를 낮추는지 확인할 방법이 없었기 때문이다. 온도를 단순히 외부에서 40℃, 45℃, 50℃와 같이 순서대로 입력하는 방식은 비교기 회로의 전환 여부만 확인할 수 있을 뿐, 팬이 냉각에 미치는 영향을 표현하지 못했다.

즉, 초기 설계는 온도를 입력으로 받아 팬의 상태를 출력하는 개방루프 시험에 가까웠다.

미리 정한 온도
→ 회로
→ 팬 ON/OFF

하지만 실제로 구현하고자 한 시스템은 팬의 출력이 다시 온도에 영향을 주는 구조였다.

온도 상승
→ 팬 ON
→ 냉각 발생
→ 온도 하강
→ 팬 OFF
→ 다시 온도 상승

따라서 이 프로젝트의 본질은 단순한 온도 스위치가 아니라, 전기회로와 열 시스템이 서로 영향을 주는 폐루프 온도 제어 시스템이라는 것을 알게 되었다.

🚨 첫 번째 문제: 50℃ 하나만 기준으로 하면 팬이 불안정하게 동작할 수 있음

처음에는 다음과 같이 하나의 기준온도만 설정하려고 했다.

50℃ 미만 → 팬 OFF
50℃ 이상 → 팬 ON

그러나 온도가 정확히 50℃ 부근에 있을 때는 문제가 발생할 수 있다.

예를 들어 온도가 49.99℃에서 50.01℃로 조금 상승하면 팬이 켜진다. 팬이 켜지면 온도가 곧바로 49.99℃로 내려갈 수 있고, 그러면 팬은 다시 꺼진다. 팬이 꺼지면 온도가 다시 상승하여 팬이 켜진다.

이 과정이 반복되면 다음과 같은 현상이 발생한다.

49.99℃ → 팬 OFF
50.01℃ → 팬 ON
49.99℃ → 팬 OFF
50.01℃ → 팬 ON

실제 센서에는 저항 오차, 전기적 잡음, 전원 변동, 비교기의 입력 오프셋 등이 존재하므로 기준점 근처에서 출력이 빠르게 반복 전환될 가능성이 있다.

이를 일반적으로 채터링 또는 경계점 부근의 불안정한 스위칭 문제로 볼 수 있다.

모터가 짧은 시간 간격으로 계속 켜졌다 꺼지면 다음과 같은 문제가 발생할 수 있다.

모터 기동전류가 반복해서 발생한다.
MOSFET의 스위칭 횟수가 불필요하게 증가한다.
전원선에 전압 변동과 잡음이 생길 수 있다.
팬이 충분한 냉각 효과를 만들기 전에 꺼질 수 있다.
실제 시스템에서 소음과 진동이 증가할 수 있다.
센서의 미세한 측정 오차가 제어 출력에 직접 반영된다.

따라서 단일 기준점 하나만으로 팬을 제어하는 것은 안정적인 온도 제어 방식이 아니라고 판단하였다.

🔍 해결 방향: ON 온도와 OFF 온도를 분리

이 문제를 해결하기 위해 팬이 켜지는 온도와 꺼지는 온도를 서로 다르게 설정하였다.

최종적으로 설정한 목표는 다음과 같다.

온도 상승 시 50℃에서 팬 ON
온도 하강 시 45℃에서 팬 OFF

이 조건에서는 45~50℃ 구간에서 팬 상태가 온도 하나만으로 결정되지 않는다. 시스템이 이전에 어떤 상태였는지에 따라 팬 상태가 달라진다.

온도가 낮은 상태에서 상승하는 경우
40℃ → 팬 OFF
45℃ → 팬 OFF
48℃ → 팬 OFF
50℃ → 팬 ON
팬이 켜진 뒤 온도가 하강하는 경우
50℃ → 팬 ON
48℃ → 팬 ON
46℃ → 팬 ON
45℃ → 팬 OFF

따라서 45~50℃ 범위는 팬이 무조건 켜지거나 무조건 꺼지는 영역이 아니다.

온도가 아래에서 올라오는 중
→ 팬 OFF 상태 유지

온도가 위에서 내려오는 중
→ 팬 ON 상태 유지

이처럼 이전 출력 상태를 유지하는 구조를 히스테리시스라고 이해하였다.

히스테리시스는 단순한 온도 범위가 아니라, 시스템에 상태 기억 기능을 부여하는 방법이었다. 비교기의 양의 되먹임을 이용하면 별도의 메모리 소자를 사용하지 않고도 출력 상태에 따라 기준전압을 변화시킬 수 있다.

이 프로젝트에서 히스테리시스는 단순한 부가 기능이 아니라, 팬의 불필요한 반복 스위칭을 억제하고 충분한 냉각 구간을 확보하기 위한 핵심 설계 조건이 되었다.

🧩 전체 시스템을 기능별 블록으로 분리

처음에는 회로 전체를 한 번에 완성하려고 하였다. 하지만 부품 수가 늘어나면서 모터가 작동하지 않을 때 어느 부분이 문제인지 판단하기 어려워졌다.

따라서 시스템을 다음과 같은 기능 블록으로 분리하였다.

① 온도 감지부
R3 10kΩ
R4 NTC Thermistor

R4는 25℃에서 10kΩ이며, Beta 값은 3950으로 설정하였다.

LTspice에서 사용한 NTC 모델은 다음과 같다.

R=R25*exp(Beta*(1/(V(TEMP_MON)+273.15)-1/298.15))

여기서 V(TEMP_MON)은 실제 전원전압이 아니라 온도를 나타내기 위해 사용한 가상 신호다.

V(TEMP_MON)=40V → 40℃
V(TEMP_MON)=50V → 50℃

온도를 전압으로 표현함으로써 LTspice의 전기회로 계산 안에서 열 상태를 다룰 수 있도록 하였다.

② 온도 판정부
LT1016 고속 비교기
R5 68kΩ 히스테리시스 저항
R6 10kΩ
R9 3.9kΩ

LT1016은 NTC 분압 전압과 기준전압을 비교한다.

R5는 비교기 출력을 기준전압 쪽으로 되먹임하여, 출력 상태에 따라 서로 다른 전환점을 형성한다.

비교기 출력 LOW
→ 한쪽 기준전압 형성

비교기 출력 HIGH
→ R5를 통해 기준전압 이동
→ 다른 전환점 형성

이를 통해 온도 상승 시 팬이 켜지는 지점과 온도 하강 시 팬이 꺼지는 지점을 분리할 수 있다.

③ 신호 발생부
NE555
R1, R8, R11
D1, D2
C2

LT1016의 출력은 NE555의 동작 허가 신호로 전달된다.

NE555는 저항, 다이오드, 커패시터로 구성된 타이밍 회로를 통해 MOSFET을 구동할 신호를 만든다.

처음에는 비교기 출력만으로 MOSFET을 직접 제어하는 단순한 방법도 고려할 수 있었지만, 최종 회로에서는 다음 구조를 유지하였다.

LT1016
→ NE555
→ MOSFET

이 구조는 추후 팬 속도 조절이나 PWM 듀티비 변경으로 확장할 수 있다는 장점이 있다.

④ 전력 스위칭부
NE555 OUT
→ R2 100Ω
→ NMOS 게이트

MOSFET은 NE555의 작은 제어신호로 팬에 흐르는 전류를 스위칭한다.

회로는 로우사이드 스위칭 방식으로 구성하였다.

5V
│
팬
│
MOSFET 드레인
MOSFET 소스
│
GND

MOSFET 게이트가 LOW이면 팬의 양단 전압 차이가 거의 없어 팬이 멈춘다.

MOSFET 게이트가 HIGH이면 드레인 전압이 GND 방향으로 내려가고, 팬 양단에 전압이 걸려 팬이 동작한다.

⑤ 열 시스템 모델

전기회로만으로는 팬이 R4의 온도를 낮추는 현상을 표현할 수 없다. 따라서 열 시스템을 전기회로의 등가 모델로 구현하였다.

최종 파일에서 사용한 값은 다음과 같다.

Tamb  = 25
Rth   = 5
Cth   = 0.5
Pheat = 6
Pcool = 15

팬 상태는 단순한 명령 신호가 아니라 실제 팬 모델의 V(RPM)을 이용해 판단하였다.

V(RPM)>0.5
→ 팬 회전 상태
→ 냉각항 활성화

따라서 전기회로의 최종 출력이 열 시스템의 입력으로 다시 연결된다.

온도
→ NTC 저항
→ 비교기
→ NE555
→ MOSFET
→ 팬 회전
→ 냉각량 변화
→ 온도

이 단계에서 프로젝트는 비로소 폐루프 구조를 갖게 되었다.

🧪 시뮬레이션에서 확인한 실제 결과

시뮬레이션 초기온도는 다음 명령으로 40℃로 설정하였다.

IC=40

따라서 첫 번째 온도 변화는 약 40℃에서 시작한다.

이후 발열량이 자연방열량보다 크기 때문에 온도가 상승하였다.

온도가 상한 전환점에 도달하자 V(RPM)이 약 10V로 상승하였고, 이는 팬 모델이 동작 상태로 전환되었음을 의미한다.

팬이 동작하면 열 모델의 냉각항이 활성화된다.

-Pcool*if(V(RPM)>0.5,1,0)

그 결과 온도는 빠르게 하강하였다. 하한 전환점에 도달하면 V(RPM)이 다시 0V가 되고, 냉각항이 제거되어 온도가 다시 상승하였다.

파형에서 관찰된 동작은 다음과 같다.

초기온도 약 40℃
↓
온도 상승
↓
약 48.7℃에서 팬 동작
↓
온도 하강
↓
약 45.8℃에서 팬 정지
↓
온도 재상승
↓
반복

V(TEMP_MON)과 V(RPM)을 동시에 확인했을 때, 온도 하강 구간과 팬 동작 구간이 일치하였다.

즉, 단순히 팬 제어신호만 발생한 것이 아니라 팬의 작동 상태가 열 모델에 반영되어 실제로 온도를 낮추는 폐루프 시뮬레이션이 형성되었다.

⚠️ 목표값과 실제 결과의 차이

최초 목표는 다음과 같았다.

50℃에서 ON
45℃에서 OFF

하지만 현재 파형에서는 대략:

약 48.7℃에서 ON
약 45.8℃에서 OFF

가 관찰된다.

또한 파형이 처음 40℃에서 시작하므로 겉으로 보면 40~49℃ 사이를 반복하는 것처럼 오해할 수 있다.

그러나 40℃는 팬의 OFF 기준온도가 아니다.

C_TH TEMP_MON 0 {Cth} IC=40

의 IC=40 때문에 시뮬레이션이 40℃에서 시작한 것뿐이다.

첫 번째 동작 이후 정상상태에서는 대략 45.8~48.7℃ 사이를 반복한다.

현재 단계에서 확인된 것은 다음 두 가지다.

폐루프 온도 제어의 전체 동작은 성공하였다.
전환온도는 목표값과 약간 차이가 있으므로 추가 보정이 필요하다.

이 차이를 단순한 실패로 판단하지 않고, 비교기의 실제 출력 전압, 히스테리시스 저항망, NE555와 팬 모델의 지연, 열 모델의 냉각 기울기를 각각 분리해 분석하기로 하였다.

이 문제는 이후 시행착오에서 별도로 다룬다.

✅ 최종 결과

초기에는 “50℃가 되면 팬을 켜는 회로”를 만들려고 하였다.

하지만 설계를 진행하면서 다음 요구사항이 추가되었다.

온도 감지
+ 비교기 판단
+ 히스테리시스 상태 유지
+ PWM 신호 발생
+ 전력 MOSFET 스위칭
+ 팬 모델
+ 열용량
+ 자연방열
+ 강제냉각
+ 출력의 온도 되먹임

최종적으로 LTspice에서 다음 동작을 확인하였다.

초기온도 40℃에서 온도가 상승한다.
상한 온도에 도달하면 팬 모델이 동작한다.
V(RPM)이 약 10V로 상승한다.
팬의 동작이 열 모델의 냉각항을 활성화한다.
온도가 하강한다.
하한 온도에 도달하면 팬이 정지한다.
다시 발열에 의해 온도가 상승한다.
이 과정이 지속적으로 반복된다.

목표였던 45~50℃와 완전히 일치하지는 않았지만, 전기회로와 열 시스템이 서로 영향을 주는 폐루프 제어의 기본 동작을 구현하였다.

💡 배운 점

이 시행착오에서 가장 크게 배운 것은 회로의 출력이 실제 제어 대상에 어떤 영향을 미치는지까지 모델링해야 한다는 점이다.

단순히 비교기 출력이 HIGH가 되는 것만 확인했다면 팬 제어신호의 발생 여부만 검증한 것이다.

하지만 실제 시스템에서 중요한 것은 다음 과정 전체다.

출력 발생
→ 전력소자 동작
→ 팬 회전
→ 열 제거
→ 온도 변화

⚡ 시행착오 02. NTC를 시간가변 저항으로 구현하며 발생한 LTspice 수식 해석 오류
📌 문제

프로젝트의 첫 번째 단계에서는 온도가 50℃에 도달했을 때 팬을 켜고, 팬이 동작하면 다시 온도가 내려가는 폐루프 구조를 정의하였다.

그러나 폐루프 제어를 구현하려면 가장 먼저 해결해야 할 문제가 있었다.

LTspice에서 R4를 단순한 10kΩ 저항이 아니라, 온도에 따라 저항값이 계속 변하는 NTC Thermistor로 표현해야 했다.

일반 저항은 시뮬레이션 도중 값이 변하지 않는다.

예를 들어 R4의 값을 다음과 같이 입력하면:

10k

시뮬레이션이 시작된 순간부터 종료될 때까지 계속 10kΩ을 유지한다.

하지만 NTC Thermistor는 온도가 상승할수록 저항이 감소한다. 따라서 온도 변화에 따라 R4의 저항도 실시간으로 다시 계산되어야 했다.

필요한 신호 흐름은 다음과 같았다.

온도 변화
↓
R4의 저항값 변화
↓
R3-R4 분압 전압 변화
↓
LT1016 입력 전압 변화
↓
팬 ON/OFF 결정

R4가 온도에 따라 변하지 않는다면 열 모델에서 온도를 아무리 변화시켜도 비교기 입력은 변하지 않는다. 그러면 팬이 온도에 반응하는 것이 아니라 고정된 전압만 비교하게 된다.

따라서 R4의 온도 의존성을 구현하는 것은 단순한 부품 모델링 문제가 아니라, 전체 제어루프가 성립하기 위한 출발점이었다.

🔍 NTC Thermistor의 저항–온도 관계 분석

사용한 NTC의 조건은 다음과 같이 설정하였다.

25℃ 기준 저항 R25 = 10kΩ
Beta 값          = 3950

NTC의 저항값은 Beta 모델을 이용하여 계산하였다.

R(T)=R

T

각 항의 의미는 다음과 같다.

R(T)   : 현재 온도에서의 NTC 저항
R25    : 25℃에서의 저항, 10kΩ
Beta   : NTC 재료 특성을 나타내는 상수, 3950
TK     : 현재 절대온도
298.15 : 25℃를 Kelvin으로 변환한 값

LTspice 열 모델에서는 온도를 섭씨로 표현하고 있었기 때문에, 수식 안에서 Kelvin으로 변환해야 했다.

절대온도 = 섭씨온도 + 273.15

따라서 최종적인 저항식은 다음 형태가 되었다.

R25*exp(
    Beta*(
        1/(온도+273.15)
        -1/298.15
    )
)

온도가 25℃일 때는 두 역수 항이 같아진다.

1/298.15 - 1/298.15 = 0

그리고:

exp(0)=1

이므로:

R(25℃)=R25=10kΩ

가 된다.

온도가 25℃보다 높아지면:

1/(T+273.15)

값이 작아지고, 지수 부분이 음수가 된다. 따라서 전체 저항은 10kΩ보다 작아진다.

즉 수식 자체는 NTC 특성과 일치하였다.

온도 상승
→ 지수항 감소
→ R4 저항 감소

이론식에는 문제가 없었지만, 이를 LTspice에 입력하는 과정에서 예상하지 못한 오류가 반복적으로 발생하였다.

🚨 첫 번째 실패: 사용자 함수로 온도 변화를 작성

초기에는 온도가 시간에 따라 다음과 같이 변하도록 설정하려고 했다.

40℃ → 45℃ → 50℃ → 55℃ → 50℃ → 45℃ → 40℃

이를 위해 사용자 함수를 정의하였다.

.func TEMPX(t) table(t,
    0,40,
    1,45,
    2,50,
    3,55,
    4,50,
    5,45,
    6,40
)

그리고 R4를 다음처럼 작성하였다.

{R25*exp(
    Beta*(
        1/(TEMPX(time)+273.15)
        -1/298.15
    )
)}

수식의 의도는 명확했다.

현재 시뮬레이션 시간 time
↓
TEMPX(time)으로 현재 온도 계산
↓
현재 온도로 R4 저항 계산

하지만 LTspice 26.0.2에서 시뮬레이션을 실행하자 다음 오류가 발생하였다.

No such parameter defined.

R4 0 N001
{R25*exp(Beta*(1/(TEMPX(time)+273.15)-1/298.15))}

오류 위치는 time 부근을 가리켰다.

처음에는 TEMPX 함수가 제대로 등록되지 않은 것으로 판단하였다. 또는 TEMP라는 이름이 LTspice 내부 온도 예약어와 충돌했을 가능성을 의심하였다.

그래서 함수 이름을 다음과 같이 변경하였다.

TEMP → TDEG

수정된 식은 다음과 같았다.

.func TDEG(t) table(...)
{R25*exp(
    Beta*(
        1/(TDEG(time)+273.15)
        -1/298.15
    )
)}

그러나 오류는 그대로 발생하였다.

이 단계에서 첫 번째 가설이 틀렸음을 확인하였다.

문제는 함수 이름 자체가 아니라, 일반 저항의 값 입력란에서 시간에 의존하는 식이 해석되는 방식에 있었다.

🚨 두 번째 실패: 함수 없이 table(time, …)을 직접 입력

사용자 함수가 원인일 수 있다고 판단하여 함수 호출을 완전히 제거하였다.

R4 안에 온도 변화를 직접 입력하였다.

{R25*exp(
    Beta*(
        1/(
            (
                table(
                    time,
                    0,40,
                    2,40,
                    5,55,
                    7,55,
                    10,40,
                    12,40
                )
            )
            +273.15
        )
        -1/298.15
    )
)}

이 방식이라면 함수 정의를 따로 읽을 필요가 없으므로 문제가 해결될 것으로 예상하였다.

그러나 LTspice는 다시 다음과 같은 오류를 출력하였다.

No such parameter defined.

이번에도 오류 표시가 time을 가리켰다.

이 결과는 중요한 단서를 제공하였다.

사용자 함수 사용 → 오류
table() 직접 사용 → 동일한 오류

즉, 문제가 TEMPX() 또는 TDEG() 함수에 있는 것이 아니었다.

LTspice는 당시 R4의 Value 식을 시간에 따라 계산하는 식이 아니라, 시뮬레이션 시작 전에 한 번 결정되는 고정 파라미터 식으로 해석하고 있었다.

따라서 time을 시간 변수로 인식하지 않고, 정의되지 않은 이름의 파라미터로 판단한 것이다.

🔍 오류의 본질: 일반 저항과 행동형 저항의 차이

LTspice에서 일반 저항에 다음과 같이 값을 입력하면:

10k

이는 고정 저항이다.

다음처럼 파라미터를 이용해도:

{Rvalue}

Rvalue가 시뮬레이션 시작 전에 정해지는 파라미터라면 역시 고정 저항으로 사용할 수 있다.

예를 들어:

.param Rvalue=10000
{Rvalue}

는 정상적으로 동작한다.

하지만 time은 시뮬레이션이 진행되는 동안 계속 변하는 독립변수다.

0초
0.1초
0.2초
...

따라서 저항값이 time에 따라 변하려면 LTspice에 이 소자가 단순한 고정 저항이 아니라 행동형 저항이라는 사실을 명확히 알려야 했다.

최종적으로 R4 Value 앞에 다음 접두어를 추가하였다.

R=

수정된 형태는 다음과 같았다.

R=R25*exp(
    Beta*(
        1/(
            V(TEMP_MON)+273.15
        )
        -1/298.15
    )
)

R=을 붙인 뒤 LTspice는 식을 단순 파라미터가 아니라, 시뮬레이션 중 계속 재평가되는 저항값으로 처리하였다.

이 수정으로 No such parameter defined 오류가 해결되었다.

🛠 온도를 시간표에서 열 상태 노드로 변경

초기 시험에서는 온도를 다음과 같이 외부에서 강제로 변화시켰다.

table(time, ...)

그러나 이 방식은 비교기 기능을 시험하기에는 유용하지만, 팬이 온도에 영향을 주는 실제 폐루프 시뮬레이션에는 적합하지 않았다.

온도가 미리 정해져 있으면 팬이 켜져도 온도 그래프는 예정된 경로를 그대로 따라간다.

팬 OFF여도 온도 하강
팬 ON이어도 온도 상승

같은 비현실적인 상황이 발생할 수 있다.

따라서 최종 설계에서는 시간표를 제거하고, 온도 자체를 하나의 상태 변수로 만들었다.

온도 상태를 나타내는 노드를 다음과 같이 정의하였다.

TEMP_MON

그리고 열용량을 커패시터로 표현하였다.

C_TH TEMP_MON 0 {Cth} IC=40

이 명령의 의미는 다음과 같다.

TEMP_MON 노드 전압
→ 현재 온도

Cth
→ 열용량

IC=40
→ 시뮬레이션 시작온도 40℃

전기회로에서 커패시터 전압은 순간적으로 변할 수 없다. 전류가 흐르면서 시간에 따라 충전되거나 방전된다.

이를 열 시스템에 대응시키면:

커패시터 전압
↔ 온도

커패시터 전류
↔ 열유량

커패시턴스
↔ 열용량

으로 해석할 수 있다.

이 구조를 이용하면 온도가 계단처럼 즉시 변하지 않고, 발열과 냉각량에 따라 연속적으로 올라가거나 내려간다.

R4의 최종 Value는 다음과 같이 구성하였다.

R=R25*exp(
    Beta*(
        1/(V(TEMP_MON)+273.15)
        -1/298.15
    )
)

이제 R4는 시간 자체를 직접 참조하지 않는다.

대신 현재 온도 상태인 V(TEMP_MON)을 읽는다.

열 모델이 TEMP_MON 결정
↓

↓
R4 저항값 변화

↓

↓

이 구조를 통해 온도, 센서, 비교기, 팬이 하나의 폐루프로 연결되었다.

📌 문제

NTC Thermistor를 LTspice에서 온도에 따라 변하는 저항으로 구현한 뒤, 다음 목표는 LT1016 비교기가 원하는 온도에서 출력 상태를 변경하도록 만드는 것이었다.

다만 LT1016에는 서로 반대로 동작하는 두 개의 출력이 있으므로, 실제 회로에서는 입력 방향과 선택한 출력 핀을 함께 확인해야 했다.

입력을 올바르게 연결해도 반대 출력을 사용하면 팬의 동작 방향이 다시 반대로 바뀔 수 있다.

따라서 다음 두 신호를 모두 확인하는 과정이 필요했다.

센서 전압이 온도에 따라 어느 방향으로 변하는가
LT1016의 두 출력 중 어느 출력이 고온에서 HIGH가 되는가

이 문제는 이후 LT1016 심볼의 핀을 해석하는 시행착오로 이어졌다.

🧪 LTspice에서 검증한 방법

계산 결과만으로 회로 연결을 확정하지 않고, LTspice에서 온도와 센서 전압을 함께 확인하였다.

R3와 R4 사이 노드에 다음 라벨을 부여하였다.

NTC_SENSE

V(TEMP_MON)

TEMP_MON 상승
→ NTC_SENSE 하강

TEMP_MON 하강
→ NTC_SENSE 상승

🔍 가변저항 사용 여부에 대한 재검토

초기에는 기준전압을 조정하기 위해 가변저항을 사용하려고 하였다.

가변저항을 사용하면 시뮬레이션이나 실물 제작에서 임계점을 직접 조절할 수 있다는 장점이 있다.

가변저항 조절
→ 기준전압 변화
→ 팬 동작 온도 변화

하지만 가변저항의 눈금만 움직이면서 50℃에 맞추는 방식은 설계 근거가 부족할 수 있었다.

왜 해당 저항비가 50℃에 해당하는지 설명할 수 없기 때문이다.

따라서 설계 순서를 다음과 같이 변경하였다.

① 목표온도 결정

② 목표온도에서 NTC 저항 계산

③ 분압전압 계산

④ 필요한 기준전압 범위 계산

⑤ 고정저항 또는 가변저항 범위 선정

⑥ LTspice 파형으로 검증

⑦ 실물에서 가변저항으로 미세 보정

이 방식에서는 가변저항이 계산을 대신하는 부품이 아니라, 저항 허용오차와 NTC 편차를 보정하는 부품이 된다.

시뮬레이션에서는 먼저 고정저항으로 원리를 검증하고, 실제 제작 단계에서는 가변저항 또는 다회전 트리머를 사용해 전환점을 조절하는 방향이 더 적절하다고 판단하였다.

⚠️ 계산값이 실제 전환점과 정확히 일치하지 않을 수 있는 이유

45℃와 50℃에서의 이상적인 센서 전압은 계산할 수 있었지만, 실제 전환온도는 다음 요소의 영향을 받을 수 있다.

NTC 허용오차

10kΩ NTC라고 하더라도 실제 25℃ 저항은 정확히 10,000Ω이 아닐 수 있다.

Beta 값 오차

Beta=3950도 대표값이며 실제 부품마다 편차가 존재한다.

고정저항 오차

R3가 10kΩ이라도 1% 저항이라면 실제값이 달라질 수 있다.

비교기 입력 오프셋

두 입력 전압이 완전히 같아지는 지점이 아니라 작은 오프셋을 포함한 지점에서 출력이 전환될 수 있다.

히스테리시스 피드백

R5가 연결되면 기준전압은 단순히 R6와 R9의 분압만으로 결정되지 않는다. 비교기 출력전압도 기준전압에 영향을 준다.

비교기 출력전압의 비이상성

출력 HIGH가 정확히 5V, LOW가 정확히 0V가 아닐 수 있다.

따라서 계산값은 설계의 시작점이고, 최종 전환온도는 파형을 통해 검증해야 한다.

이 관점은 이후 실제 파형이 목표했던 45~50℃가 아니라 약 45.8~48.7℃에서 반복된 원인을 분석하는 데 중요한 기반이 되었다.

✅ 결과

NTC를 단순히 “온도를 감지하는 저항”으로 보는 단계에서 벗어나, 온도를 비교기 입력전압으로 변환하는 전체 과정을 계산하였다.

최종적으로 다음 관계를 확인하였다.

45℃:
RNTC ≈ 4.35kΩ
VNTC ≈ 1.515V

50℃:
RNTC ≈ 3.59kΩ
VNTC ≈ 1.320V

따라서 비교기 회로가 만들어야 할 히스테리시스 전압 폭은 약:

1.515V - 1.320V
≈ 0.195V

임을 알 수 있었다.

또한 현재 분압회로에서는 온도가 올라갈수록 센서 전압이 낮아지므로, 기준전압을 LT1016의 비반전 입력에 연결하고 NTC 센서 전압을 반전 입력에 연결하는 방향을 설계 기준으로 정하였다.

이 계산을 통해 목표온도를 회로가 이해할 수 있는 전압 조건으로 바꿀 수 있었다.

📌 문제

NTC Thermistor의 온도 특성과 분압전압을 계산한 결과, 목표 온도에서 비교기가 확인해야 하는 전압을 구할 수 있었다.

45℃ → NTC 분압전압 약 1.515V
50℃ → NTC 분압전압 약 1.320V

현재 회로에서는 온도가 올라갈수록 R4의 저항값이 감소하고, R3와 R4 사이의 NTC_SENSE 전압도 낮아진다.

따라서 단순히 50℃에서 팬을 켜려면 비교기의 기준전압을 약 1.32V로 설정할 수 있었다.

V(NTC_SENSE) > 1.32V
→ 온도가 아직 낮음
→ 팬 OFF

V(NTC_SENSE) < 1.32V
→ 온도가 약 50℃ 이상
→ 팬 ON

그러나 기준전압을 하나만 사용하면 팬이 켜지는 온도와 꺼지는 온도가 모두 50℃ 부근으로 같아진다.

온도 상승 시 50℃ → 팬 ON
온도 하강 시 50℃ → 팬 OFF

이 방식은 회로가 논리적으로는 동작하지만, 실제 제어 시스템에서는 불안정할 가능성이 높았다.

팬이 50℃에서 켜지면 냉각으로 인해 온도가 곧바로 50℃ 아래로 내려간다. 그러면 팬이 꺼지고, 팬이 꺼지면 다시 발열로 인해 온도가 50℃를 넘는다.

결과적으로 다음과 같은 반복이 발생할 수 있다.

49.99℃ → 팬 OFF
50.01℃ → 팬 ON
49.99℃ → 팬 OFF
50.01℃ → 팬 ON

센서 노이즈나 비교기의 입력 오프셋이 전혀 없더라도, 팬의 ON/OFF 자체가 온도를 변화시키기 때문에 단일 임계점에서는 출력이 기준점 근처에서 빠르게 반복될 수 있다.

이 현상을 해결하기 위해 팬이 켜지는 온도와 꺼지는 온도를 분리해야 했다.

최종 목표는 다음과 같았다.

온도가 상승할 때:
50℃에서 팬 ON

온도가 하강할 때:
45℃에서 팬 OFF

즉 팬이 한 번 켜지면 온도가 50℃ 아래로 내려가더라도 45℃까지는 계속 작동해야 했다.

🔍 단순 비교기와 히스테리시스 비교

단순 비교기는 항상 하나의 기준전압을 사용한다.

VREF = 고정

NTC 전압이 기준전압을 통과하면 출력이 바뀌고, 다시 반대 방향으로 통과하면 같은 전압에서 원래 상태로 돌아간다.

이를 그래프로 생각하면 입력과 출력의 관계가 하나의 경계만 가진다.

VNTC > VREF → 팬 OFF
VNTC < VREF → 팬 ON

반면 히스테리시스 비교기는 현재 출력 상태에 따라 기준전압이 달라진다.

팬이 꺼져 있을 때 사용하는 기준전압
≠
팬이 켜져 있을 때 사용하는 기준전압

출력이 LOW일 때 기준전압과 출력이 HIGH일 때 기준전압을 서로 다르게 만들면, 입력이 한 번 경계를 넘어간 뒤 일정 범위 안에서는 이전 상태를 유지한다.

이번 회로에서 필요한 전압 조건은 다음과 같았다.

50℃에 해당하는 전압:
약 1.320V

45℃에 해당하는 전압:
약 1.515V

따라서 팬이 꺼져 있는 동안에는 약 1.32V를 기준으로 사용하고, 팬이 켜진 뒤에는 기준전압을 약 1.52V로 이동시켜야 했다.

팬 OFF 상태:
VNTC가 약 1.32V 아래로 내려가면 팬 ON

팬 ON 상태:
VNTC가 약 1.52V 위로 올라가면 팬 OFF

이 두 기준전압 사이의 약 0.20V가 히스테리시스 전압 폭이다.

🚨 예상과 실제 파형의 차이

최종 폐루프 파형에서는 대략 다음 결과가 나타났다.

팬 OFF: 약 45.8℃ 부근

팬 ON: 약 49.3℃
팬 OFF: 약 44.3℃

였다.

계산값과 실제 파형이 완전히 일치하지 않았다.

특히 실제 파형에서는 상한 온도가 계산값보다 약간 낮고, 하한 온도는 계산값보다 높았다. 결과적으로 실제 히스테리시스 폭이 약 3℃ 정도로 줄어든 형태가 나타났다.

이 차이를 분석하면서, 히스테리시스 회로를 단순히 저항 세 개만으로 계산하는 데에는 한계가 있다는 것을 알게 되었다.

초기 계산에서는 LT1016 출력이 정확히 다음처럼 움직인다고 가정하였다.

LOW = 0V
HIGH = 5V

하지만 실제 LT1016 모델의 출력은 연결된 부하와 내부 출력단 특성에 따라 전원 레일까지 정확히 도달하지 않을 수 있다.

현재 LT1016 출력에는 다음 경로가 연결되어 있다.

LT1016 출력
→ R5 68kΩ 피드백

LT1016 출력
→ R10 100Ω
→ NE555 RESET

즉 출력은 완전한 무부하가 아니다.

실제 LOW 전압이 0V보다 높고 HIGH 전압이 5V보다 낮으면, R5를 통해 이동하는 기준전압의 폭도 작아진다.

예를 들어 출력이 대략:

LOW ≈ 0.4V
HIGH ≈ 3.5V

라고 가정해 계산하면 기준전압에 대응하는 온도는 약:

상승 전환점 ≈ 48.9℃
하강 전환점 ≈ 45.7℃

정도가 된다.

이 값은 실제 파형에서 관찰한 약 48.7℃와 45.8℃에 매우 가깝다.

다만 현재 파형에는 V(COMP_OUT)이 함께 저장되어 있지 않으므로, 이 설명은 실제 LT1016 출력전압을 직접 측정해 확정한 결과가 아니라 회로와 파형을 기반으로 한 추정이다.

향후에는 LT1016 사용 출력에 COMP_OUT 라벨을 붙이고 다음 신호를 함께 측정해야 한다.

V(TEMP_MON)
V(NTC_SENSE)
V(VREF_HYS)
V(COMP_OUT)
V(RPM)

출력의 실제 HIGH와 LOW 값을 측정하면 R5가 기준전압을 얼마만큼 이동시키는지 정확하게 다시 계산할 수 있다.

🔍 R5 값이 하는 역할

R5는 히스테리시스의 크기를 결정하는 핵심 저항이다.

R5가 작아지면 비교기 출력이 기준전압 노드에 더 강하게 영향을 준다.

R5 감소
→ 피드백 증가
→ 기준전압 이동량 증가
→ ON/OFF 온도 차이 증가

반대로 R5가 커지면 피드백 영향이 약해진다.

R5 증가
→ 피드백 감소
→ 기준전압 이동량 감소
→ 히스테리시스 폭 감소

그러나 R5만 바꾸면 히스테리시스의 폭뿐 아니라 중심 온도도 함께 변할 수 있다.

따라서 원하는 전환점을 정확히 맞추려면 역할을 구분해야 한다.

R6, R9 비율
→ 기준전압의 중심 위치 결정

R5
→ 출력 상태에 따른 기준전압 이동량 결정

목표가 50℃ ON, 45℃ OFF라면 단순히 R5를 조정하는 것이 아니라 다음 두 조건을 동시에 만족하도록 세 저항을 계산해야 한다.

출력 LOW 상태의 VREF
≈ 50℃의 NTC 전압

출력 HIGH 상태의 VREF
≈ 45℃의 NTC 전압

그리고 계산에 사용하는 출력전압도 이상적인 0V와 5V가 아니라 LT1016의 실제 출력전압을 사용해야 한다.

🧪 히스테리시스가 실제로 작동하는지 확인한 방법

히스테리시스는 온도 파형 하나만 보고도 어느 정도 확인할 수 있다.

만약 단일 임계점 제어라면 온도는 한 기준점 주변에서 매우 짧은 폭으로 반복될 가능성이 높다.

반면 현재 파형에서는 온도가 상승하여 상한에 도달한 뒤 팬이 켜지고, 온도가 상당히 내려간 후에야 팬이 꺼졌다.

온도 상승 구간
→ V(RPM)=0V

상한 도달
→ V(RPM) 약 10V

온도 하강 중 45~48℃ 구간
→ V(RPM) 약 10V 유지

하한 도달
→ V(RPM)=0V

특히 온도가 48℃에서 하강하고 있을 때 팬이 계속 동작하는 것은 중요한 결과다.

온도 하나만 기준으로 즉시 팬 상태가 결정된다면 48℃는 50℃보다 낮기 때문에 팬이 이미 꺼져야 한다. 하지만 실제 파형에서는 팬이 상한에서 한 번 켜진 뒤 하한까지 유지되었다.

이는 45~50℃ 사이에서 출력이 이전 상태를 기억한다는 것을 의미한다.

온도가 상승하며 48℃
→ 팬 OFF

온도가 하강하며 48℃
→ 팬 ON

동일한 온도에서도 이동 방향과 이전 상태에 따라 출력이 달라지는 것이 히스테리시스의 핵심이다.

❌ 잘못 이해했던 부분

처음에는 히스테리시스를 단순히 다음과 같은 온도 범위라고 생각하였다.

45~50℃에서는 팬이 켜짐

하지만 이는 정확한 설명이 아니었다.

45~50℃ 구간에서 팬은 항상 켜지는 것이 아니다.

온도가 아래에서 상승 중
→ 45~50℃에서 팬 OFF 유지

50℃를 넘어 팬이 켜진 뒤 하강 중
→ 45~50℃에서 팬 ON 유지

즉 히스테리시스는 특정 범위에서 팬을 무조건 켜는 기능이 아니라, 해당 범위에서 이전 상태를 유지하는 기능이다.

또한 R5가 단순히 출력에 연결된 추가 저항이라고 생각했지만, 실제로는 기준전압 자체를 출력 상태에 따라 이동시키는 역할을 한다.

이 때문에 R5는 비교기 출력의 HIGH·LOW 전압, R6와 R9의 값, 입력 연결 방향과 함께 분석해야 했다.

✅ 결과

R6, R9로 기준전압을 만들고 R5를 LT1016 출력에서 기준전압 노드로 연결하여 양의 되먹임 회로를 구성하였다.

이상적인 0V/5V 출력을 기준으로 계산한 전환점은 다음과 같았다.

상승 시 약 49.27℃에서 팬 ON
하강 시 약 44.27℃에서 팬 OFF

최종 시뮬레이션 파형에서는 대략:

상승 시 약 48.7℃에서 팬 ON
하강 시 약 45.8℃에서 팬 OFF

가 관찰되었다.

목표값인 50℃와 45℃에 정확히 일치하지는 않았지만, 다음 기능은 정상적으로 구현되었다.

팬이 상한 온도에서 켜짐
온도가 내려가도 즉시 꺼지지 않음
중간 온도 구간에서 팬 ON 상태 유지
하한 온도에 도달한 뒤 팬 OFF
팬 정지 후 다시 온도 상승
주기적인 폐루프 동작 형성

따라서 R5 양의 되먹임을 이용한 히스테리시스의 원리와 기능은 검증되었다.

비교기 출력이 기준전압 생성에 직접 사용되는 회로에서는 출력전압의 비이상성이 단순한 출력 오차로 끝나지 않는다. 피드백 전압이 달라지고, 결국 시스템이 동작하는 온도까지 바뀐다.

따라서 정확한 히스테리시스 설계에는 입력 전압뿐 아니라 출력단의 실제 동작 범위도 포함해야 한다.

🏭 반도체·전력·냉각 분야에서의 의미

전력반도체 냉각 시스템에서는 팬이 특정 온도 근처에서 빠르게 켜졌다 꺼지는 현상을 방지해야 한다.

모터나 팬은 기동 순간에 정상 운전보다 큰 전류가 흐를 수 있으며, 반복 기동은 전원과 스위칭 소자에 부담을 줄 수 있다.

히스테리시스 폭이 너무 작으면 채터링 문제가 다시 발생하고, 너무 크면 온도 변화 폭이 커져 부품이 높은 온도에 오래 노출될 수 있다.

따라서 히스테리시스는 단순한 회로 안정화 기능이 아니라 열 스트레스와 팬 수명 사이의 절충 조건으로 설계해야 한다.

V(RPM) = 0V

시뮬레이션 시간이 지나고 TEMP_MON의 온도가 상승해도 V(RPM)은 계속 0V에 머물렀다. 팬 모델이 회전하지 않으므로 열 모델의 냉각항 역시 활성화되지 않았고, 온도는 올라가거나 특정 값에서 유지될 뿐 다시 내려가지 않았다.

NE555 RESET

초기에는 모터 모델이나 MOSFET이 잘못된 것으로 판단하기 쉬웠다. 하지만 신호를 출력단에서 입력단 방향으로 역추적한 결과, 문제의 출발점은 LT1016 비교기 주변에 있었다.

🚨 관찰된 이상 현상

모터가 동작하려면 다음 조건이 필요하다.

LT1016 출력 전환
→ NE555 RESET 활성화
→ NE555 OUT에서 구동신호 발생
→ MOSFET 게이트 전압 상승
→ FAN_MINUS 전압 하강
→ 팬 양단에 전압 발생
→ V(RPM) 상승

그러나 실제 결과는 다음과 같았다.

온도 변화: 발생
NTC 저항 변화: 발생
팬 회전: 없음
V(RPM): 0V 유지

이는 열 모델이 실패한 것이 아니라, 열 모델에 팬 작동 신호가 전달되지 않는다는 의미였다.

팬 냉각식은 다음과 같이 구성되어 있었다.

B_TH 0 TEMP_MON I={
Pheat
-(V(TEMP_MON)-Tamb)/Rth
-Pcool*if(V(RPM)>0.5,1,0)
}

여기에서 V(RPM)>0.5가 참이 되어야 Pcool이 적용된다.

하지만 V(RPM)=0이면 식은 다음과 같이 단순화된다.

Pheat
-(V(TEMP_MON)-Tamb)/Rth

즉 팬 냉각항이 완전히 사라진다.

따라서 온도가 내려가지 않는 현상은 단순히 Pcool 값이 작아서가 아니었다. 팬이 아예 ON 상태로 들어가지 못하고 있었기 때문이다.

🔍 최초 가설

처음에는 가장 뒤쪽 부품부터 의심하였다.

가설 1. 팬 모델이 잘못되었을 가능성
FAN5V.lib가 정상적으로 포함되지 않았거나,
X_FAN 단자 순서가 잘못되었을 수 있다.
가설 2. MOSFET 모델이 잘못되었을 가능성

초기 MOSFET 모델에는 일반 NMOS 모델에서 사용할 수 없는 다음 파라미터가 포함되어 있었다.

.model NMOS_FAN NMOS(Vto=2 Ron=0.05 Roff=10Meg)

이를 다음처럼 수정하였다.

.model NMOS_FAN NMOS(
    Level=1
    Vto=2
    Kp=20
    Lambda=0.01
)

하지만 MOSFET 모델을 수정해도 게이트 입력이 0V라면 팬은 작동하지 않는다.

가설 3. NE555가 출력하지 않는 문제

NE555의 RESET이 LOW이면 출력은 강제로 비활성화된다.

따라서 LT1016 출력이 NE555의 RESET으로 정상 전달되는지 확인할 필요가 있었다.

결국 문제를 다음 신호 흐름으로 나누어 확인하였다.

LT1016 출력
→ NE555 RESET
→ NE555 OUT
→ MOSFET GATE
→ FAN_MINUS
→ RPM

이 과정에서 비교기 출력 자체가 원하는 방향으로 변하지 않는다는 사실을 확인하였다.

🧩 문제의 핵심: LT1016 심볼이 90도 회전되어 있었음

LTspice 회로에서 U3 LT1016은 일반적으로 데이터시트에서 보는 방향이 아니라 90도 회전된 상태였다.

일반적인 비교기 심볼은 다음처럼 생각하기 쉽다.

왼쪽  : +입력, -입력
오른쪽: 출력
위쪽  : 양전원
아래쪽: 음전원

그러나 현재 LTspice 화면의 LT1016은 그런 형태가 아니었다.

화면에 나타난 핀 배치는 다음과 같았다.

왼쪽 3개 핀
오른쪽 1개 핀
위쪽 2개 핀
아래쪽 2개 핀

또한 핀 주변에 +, -, L, G 같은 짧은 문자만 표시되어 있었다.

문제는 +와 - 문자가 두 가지 의미로 사용된다는 점이었다.

전원용 V+, V-
비교입력용 IN+, IN-

둘 다 같은 +, - 기호를 사용하므로, 심볼의 위치를 정확히 구분하지 않으면 전원핀과 비교입력핀을 서로 바꿔 연결할 수 있었다.

LT1016은 단일 5V 전원에서도 사용할 수 있으며, 입력 비교핀과 전원핀 외에 LATCH, 출력용 GND, 서로 반대 상태를 내는 두 개의 complementary output을 갖는다. LATCH를 HIGH로 유지하면 당시의 입력 상태가 출력에 보존된다.

즉 이 부품은 일반적인 5핀 비교기보다 연결해야 할 핀이 많았고, 심볼이 회전된 상태에서는 핀 기능을 외형만 보고 추측해서는 안 되었다.

🛠 심볼을 위치별로 다시 분류

회전된 U3 심볼을 화면에 보이는 위치 그대로 분해하였다.

                 위쪽 왼쪽       위쪽 오른쪽
                    +                  -
                    │                  │
              ┌──────────────────────────┐
왼쪽 위   - ──┤                          ├── + 오른쪽
왼쪽 중간 L ──┤         LT1016           │
왼쪽 아래 G ──┤                          │
              └──────────┬──────┬────────┘
                       아래 1   아래 2
                       출력     반전출력

각 위치의 역할은 다음과 같이 정리하였다.

화면상 위치	실제 역할
왼쪽 위 -	음전원 V−
왼쪽 가운데 L	LATCH
왼쪽 아래 G	출력단 GND
오른쪽 +	양전원 V+
위쪽 왼쪽 +	비반전 입력 IN+
위쪽 오른쪽 −	반전 입력 IN−
아래쪽 출력 1	비교기 출력 Q
아래쪽 출력 2	반전 출력 /Q

이렇게 분류하면서 가장 먼저 깨달은 점은 다음과 같았다.

위쪽에 보이는 +, −는 전원핀이 아니라 두 전압을 비교하는 입력이고, 왼쪽과 오른쪽에 있는 −, +가 실제 전원핀이다.

초기에는 +, -라는 문자만 보고 연결하려고 했기 때문에 비교기의 전원과 입력을 혼동할 가능성이 컸다.

🔧 전원핀 수정

LT1016을 단일 5V 전원으로 사용하기 위해 전원핀을 다음처럼 정리하였다.

오른쪽 V+ → VCC 5V
왼쪽 V−   → GND
왼쪽 G    → GND

여기에서 왼쪽 G는 단순히 심볼 장식이 아니라 출력단 기준 GND로 사용되는 핀이므로 반드시 GND에 연결하였다.

LATCH는 출력 상태를 고정할 필요가 없는 연속 온도 비교 회로이므로 LOW로 유지하였다.

왼쪽 LATCH → GND

LATCH를 HIGH로 유지하면 입력전압이 바뀌더라도 출력이 당시 상태를 유지할 수 있다. 온도가 계속 변하는 시스템에서 이 핀이 HIGH로 묶이면 비교기가 고장 난 것처럼 출력이 한 상태에 머물 수 있다.

최종적인 보조핀 연결은 다음과 같다.

V+      → 5V
V−      → GND
G       → GND
LATCH   → GND

이 네 핀은 온도를 판단하는 입력이 아니라, 비교기가 정상 작동하기 위한 전원 및 제어 조건이다.

📐 비교입력 방향 재설정

NTC 분압회로는 다음 구조로 되어 있다.

5V
│
R3 10kΩ
│
NTC_SENSE
│
R4 NTC
│
GND

온도가 상승하면 R4의 저항이 감소하고 NTC_SENSE 전압도 감소한다.

온도 상승
→ R4 감소
→ NTC_SENSE 감소

팬은 고온에서 켜져야 하므로 다음 관계가 필요했다.

기준전압 > NTC_SENSE
→ 고온으로 판단
→ 팬 ON 방향 출력

따라서 비교입력은 다음처럼 연결하였다.

U3 위쪽 왼쪽 IN+
→ R6, R9, R5가 만나는 히스테리시스 기준전압

U3 위쪽 오른쪽 IN−
→ R3와 R4 사이의 NTC_SENSE

이 연결에서는 온도가 상승하여 NTC 전압이 기준전압보다 낮아지면:

V(IN+) > V(IN−)

상태가 되어 출력이 전환된다.

온도가 다시 낮아지면 NTC 전압이 증가하고, 히스테리시스 기준전압을 넘어선 뒤 출력이 원래 상태로 복귀한다.

🚨 아래쪽에 출력이 두 개 있다는 문제

LT1016은 출력이 하나가 아니라 서로 반대로 움직이는 두 개의 출력을 갖는다.

Q = HIGH일 때 /Q = LOW
Q = LOW일 때 /Q = HIGH

이 기능은 정상 출력과 반전 출력을 별도의 인버터 없이 선택할 수 있게 한다. LT1016의 두 출력은 TTL/CMOS 로직에 직접 연결할 수 있도록 설계된 complementary output이다.

초기에는 아래쪽에 핀이 두 개 있다는 사실 때문에 다음과 같은 혼동이 발생하였다.

두 출력을 동시에 연결해야 하는가?
한쪽은 전원핀인가?
한쪽은 출력이고 다른 한쪽은 사용하지 않는 핀인가?
어느 쪽이 고온에서 HIGH가 되는가?

두 출력은 동시에 하나의 노드로 묶어서는 안 된다. 서로 반대 상태를 출력하므로 연결하면 출력끼리 충돌할 수 있다.

따라서 두 출력 중 하나만 선택해야 했다.

선택 기준은 부품 이름이나 심볼 방향을 추측하는 것이 아니라, 원하는 시스템 동작이었다.

저온에서 LOW
고온에서 HIGH

가 되는 출력을 사용해야 했다.

선택한 출력은 다음 두 곳에 연결하였다.

선택 출력
├── R10 100Ω → NE555 RESET
└── R5 68kΩ  → VREF_HYS

다른 출력은 연결하지 않았다.

R10 경로는 NE555 동작을 허가하거나 차단하고, R5 경로는 비교기 출력 상태를 기준전압에 되먹임하여 히스테리시스를 만든다.

🔍 출력 핀을 추측하지 않고 동작으로 선택

심볼이 회전되어 있었기 때문에 아래쪽 왼쪽과 아래쪽 오른쪽 중 어느 것이 Q인지 화면만 보고 단정하면 다시 오류가 발생할 수 있었다.

따라서 출력 선택 기준을 다음처럼 바꾸었다.

1. 입력과 전원 연결을 먼저 정상화한다.

2. 아래쪽 두 출력은 서로 분리한다.

3. 각각을 임시로 OUT_A, OUT_B라고 구분한다.

4. 온도가 상승할 때 두 출력이 어떻게 변하는지 확인한다.

5. 고온에서 HIGH가 되는 쪽을 NE555 RESET에 사용한다.

6. 반대 출력은 사용하지 않는다.

이 방법은 심볼 방향을 외우는 것보다 확실했다.

40℃ 부근
OUT_A = LOW
OUT_B = HIGH

상한온도 부근
OUT_A = HIGH
OUT_B = LOW

처럼 나온다면 OUT_A를 사용한다.

반대로 나온다면 OUT_B를 사용한다.

최종 목적은 Q라는 이름을 맞히는 것이 아니라:

고온
→ 선택 출력 HIGH
→ NE555 RESET 활성화
→ 팬 ON

이라는 시스템 동작을 확보하는 것이었다.

🧪 신호를 단계별로 검증

비교기 핀을 수정한 뒤 곧바로 온도 파형만 확인하지 않고, 각 블록의 신호가 다음 단계로 전달되는지 순서대로 확인하였다.

1단계: 온도 상태
V(TEMP_MON)

초기 40℃에서 시작해 발열에 의해 상승하는지 확인하였다.

2단계: NTC 센서전압
V(NTC_SENSE)

온도가 상승할 때 반대로 감소해야 한다.

3단계: 히스테리시스 기준전압
V(VREF_HYS)

비교기 출력 상태에 따라 두 수준으로 이동해야 한다.

4단계: 비교기 사용 출력

당시 최종 파형에는 COMP_OUT 라벨을 별도로 저장하지 않았지만, 선택한 출력이 R10과 R5로 전달되는 구조를 확인하였다.

향후에는 다음 라벨을 추가하여 실제 HIGH·LOW 전압을 기록할 계획이다.

COMP_OUT
5단계: NE555 출력

비교기 출력이 NE555의 RESET을 활성화하면 NE555 OUT에서 구동 신호가 발생해야 한다.

6단계: MOSFET 게이트
V(GATE)

NE555 출력에 따라 0V와 HIGH 상태를 반복해야 한다.

7단계: 팬 회전 신호
V(RPM)

팬 OFF에서는 0V, 팬 ON 구간에서는 약 10V가 나타나야 한다.

❌ 잘못 판단했던 부분

첫째, 심볼에 표시된 +, −만 보고 핀을 판단하려고 하였다.

LT1016에는 다음 두 종류의 +, −가 동시에 존재한다.

V+, V−
IN+, IN−

따라서 문자뿐 아니라 심볼에서의 위치와 역할을 함께 확인해야 했다.

둘째, 비교기의 출력은 하나일 것이라고 생각하였다.

LT1016은 서로 반대로 움직이는 두 출력을 제공하기 때문에, 입력 방향과 출력 선택을 함께 고려해야 했다.

입력을 서로 바꾸는 방법
또는
Q와 /Q 중 반대 출력을 선택하는 방법

두 방법 모두 출력 논리를 반전시킬 수 있다.

둘을 동시에 바꾸면 결과가 다시 원래 방향으로 돌아갈 수 있으므로, 한 번에 한 요소만 수정하고 파형을 확인해야 했다.

셋째, LATCH 핀을 단순한 미사용 핀으로 생각하였다.

하지만 LATCH는 출력 상태를 보존하는 기능이 있으므로, 연속 비교가 필요한 온도 제어에서는 확실한 LOW 상태로 유지해야 했다.

넷째, 모터가 돌지 않으면 곧바로 모터나 MOSFET을 의심하였다.

실제로는 출력단의 증상인 V(RPM)=0만 보고 부품을 교체하기보다, 신호 경로를 입력 방향으로 역추적해야 했다.

✅ 결과

LT1016의 회전된 심볼을 위치별로 다시 분석하여 다음과 같이 연결하였다.

오른쪽 V+      → 5V
왼쪽 V−        → GND
왼쪽 G         → GND
왼쪽 LATCH     → GND

위쪽 IN+       → VREF_HYS
위쪽 IN−       → NTC_SENSE

아래쪽 출력 중
고온에서 HIGH가 되는 출력
→ R10 → NE555 RESET
→ R5  → VREF_HYS

반대 출력
→ 미사용

그 결과 LT1016 출력이 온도 변화에 따라 전환되었고, NE555와 MOSFET을 거쳐 팬 모델까지 신호가 전달되었다.

최종 시뮬레이션에서는:

V(RPM)=0V
↔
V(RPM)≈10V

가 반복되었으며, 이에 따라 온도도 대략:

약 46℃ ↔ 약 48~49℃

범위에서 상승과 하강을 반복하였다.

목표했던 정확한 45℃와 50℃에는 추가 보정이 필요하지만, 비교기의 핀 연결 오류를 해결한 뒤 폐루프 제어가 처음으로 완성되었다.

💡 배운 점

회로 심볼은 실제 부품의 외형이 아니라 전기적 기능을 표현한 도식이다.

심볼을 회전하면 핀 위치가 달라지지만 핀의 기능은 달라지지 않는다.

따라서 다음과 같은 방식으로 부품을 해석해야 한다.

겉모양을 보고 추측
→ 위험

🏭 반도체·전력·냉각 분야에서의 의미

전력반도체 시스템에서는 센서, 비교기, PWM 제어기, 게이트 드라이버, MOSFET이 여러 단계로 연결된다.

이 중 하나의 핀만 잘못 연결되어도 마지막 출력단에서는 단순히 다음 현상만 보일 수 있다.

팬이 안 돈다.
펌프가 안 돈다.
MOSFET이 안 켜진다.
보호회로가 작동하지 않는다.

이번 시행착오를 통해 시스템을 다음처럼 단계적으로 디버깅해야 한다는 것을 배웠다.

→ 기준전압
→ 비교기 출력
→ Enable/RESET
→ PWM 출력
→ 게이트 전압
→ 전력단 전압
→ 부하 상태

이는 전력변환기나 반도체 냉각장치에서 보호회로를 점검하는 방식과 연결된다.

실물 제작 단계에서는 심볼뿐 아니라 실제 IC의 패키지 핀 번호까지 확인해야 한다. LTspice의 심볼 위치와 실제 DIP·SO 패키지의 번호는 외형적으로 다를 수 있으므로, PCB 제작 전에는 반드시 데이터시트의 핀 번호와 회로망을 교차검증할 예정이다.
정상상태 판정 기준

이 과정을 통해 회로 설계는 부품을 연결하는 작업이 아니라, 먼저 시스템의 상태와 에너지 흐름을 정의한 뒤 각 기능을 회로 블록으로 구현하는 과정이라는 것을 배웠다.

이론적으로 각 블록의 역할은 이해하고 있었다. 그러나 시뮬레이션에서는 온도가 상승해도 팬의 회전 상태를 나타내는 V(RPM)이 계속 0V로 유지되는 경우가 있었다.

V(TEMP_MON) 상승
V(RPM) = 0V

팬이 작동하지 않으므로 냉각 모델의 Pcool 항도 활성화되지 않았다. 그 결과 온도는 계속 상승하거나 일정 온도에 가까워질 뿐, 내가 원했던 것처럼 상승과 하강을 반복하지 않았다.

처음에는 냉각 세기가 약한 것으로 판단하여 Pcool 값을 키우려고 했다. 그러나 V(RPM)=0인 상태에서는 Pcool 값을 아무리 크게 설정해도 냉각은 발생하지 않는다.

최종 열 모델은 다음과 같이 구성되어 있었기 때문이다.

B_TH 0 TEMP_MON I={
    Pheat
    -(V(TEMP_MON)-Tamb)/Rth
    -Pcool*if(V(RPM)>0.5,1,0)
}

이 식에서 팬 냉각은 다음 조건이 참일 때만 활성화된다.

V(RPM) > 0.5V

그런데 V(RPM)=0V이면 조건문은 0을 출력한다.

따라서 실제 열 모델은 다음과 같이 동작한다.

팬 OFF:

Pheat
-(V(TEMP_MON)-Tamb)/Rth

즉 발열과 자연방열만 존재하고 팬 냉각은 완전히 제외된다.

이 문제를 통해 온도가 내려가지 않는 현상을 곧바로 열 모델의 문제로 판단해서는 안 된다는 것을 알게 되었다. 온도 파형은 시스템의 최종 결과일 뿐이며, 그 이전에 비교기 출력부터 팬 회전까지의 전기적 신호 전달이 정상적으로 이루어지는지 확인해야 했다.

예를 들어 온도가 내려가지 않을 때 Pcool을 5에서 15로 높였다고 하더라도, 팬이 실제로 켜지지 않았다면 결과는 바뀌지 않는다.

반대로 팬이 켜진 상태에서 Pcool을 지나치게 크게 설정하면 온도가 너무 빠르게 내려가 목표 하한을 지나치는 현상이 나타날 수 있다.

이후에는 마지막 결과인 온도 파형만 확인하지 않고, 신호가 어느 단계까지 전달되는지를 앞에서부터 순서대로 검사하였다.

🧪 2단계: LT1016 출력과 NE555 RESET 경로 확인

LT1016은 기준전압과 NTC 센서전압을 비교한다.

고온에서 팬을 켜는 방향으로 사용한 연결은 다음과 같다.

LT1016 IN+
→ 히스테리시스 기준전압

LT1016 IN-
→ NTC_SENSE

온도가 상승하면 NTC_SENSE가 감소하므로 다음 조건이 만들어진다.

V(IN+) > V(IN-)

이때 선택한 LT1016 출력이 팬을 켜는 방향으로 전환되어야 한다.

LT1016 출력은 두 가지 역할을 동시에 수행한다.

LT1016 출력
├── R5 68kΩ → 기준전압 되먹임
└── R10 100Ω → NE555 RESET

R5 경로는 히스테리시스를 만들고, R10 경로는 NE555의 동작을 허가하거나 차단한다.

NE555의 RESET은 단순한 일반 입력이 아니다.

RESET LOW
→ NE555 출력 강제 비활성화

RESET HIGH
→ NE555 발진 가능

따라서 LT1016이 올바르게 전환되더라도 R10과 RESET 사이의 연결이 끊겨 있거나, 반대 출력 핀을 사용하면 NE555 출력은 발생하지 않는다.

이 경우 뒤쪽의 MOSFET과 팬이 아무리 정상이어도 다음 결과가 나타난다.

NE555 OUT = 0V
MOSFET GATE = 0V
V(RPM) = 0V

이 과정에서 비교기 출력은 팬을 직접 구동하는 전력이 아니라, NE555가 동작할 수 있도록 허가하는 제어신호라는 점을 구분하게 되었다.

🧪 3단계: NE555 출력 확인

최종 회로는 단순히 LT1016 출력으로 MOSFET을 직접 켜는 구조가 아니다.

LT1016
→ NE555
→ MOSFET
→ 팬

NE555는 R1, R8, R11, D1, D2, C2로 구성된 타이밍 회로와 함께 동작한다.

비교기 출력이 RESET을 HIGH로 만든다고 해서 NE555 OUT이 항상 고정 5V가 되는 것은 아니다. NE555의 타이밍 커패시터가 충전과 방전을 반복하면서 출력에 펄스가 발생한다.

따라서 게이트 파형은 다음과 같은 형태가 될 수 있다.

0V ↔ 5V 반복

이 펄스는 MOSFET을 반복적으로 켜고 끄며 팬에 전달되는 평균전력을 결정한다.

NE555의 타이밍 구조를 유지한 이유는 단순한 ON/OFF를 넘어 추후 다음 기능으로 확장할 수 있기 때문이다.

팬 속도 조절
PWM 듀티비 조절
온도에 따른 다단계 냉각
기동 시 최대 듀티 적용
정상상태에서 소음 감소

다만 현재 프로젝트에서 우선 검증한 것은 정밀한 팬 속도 제어가 아니라, 비교기의 고온 판정이 발생했을 때 NE555가 MOSFET 구동신호를 발생시키는지 여부였다.

🚨 시뮬레이션 시간 설정에 대한 두 번째 문제

최종 파일의 과도해석 명령은 다음과 같다.

.tran 0 60 0 10m startup

각 항의 의미는 다음과 같다.

→ 전체 시뮬레이션 시간 60초

60초는 온도가 여러 번 상승하고 하강하는 모습을 관찰하기에는 적절했다.

그러나 10m, 즉 10ms의 최대 시간 간격은 열 파형을 보기에는 충분할 수 있지만, NE555의 세부 PWM 파형을 분석하기에는 클 수 있다.

온도는 수초 단위로 천천히 변하지만, NE555는 훨씬 짧은 시간 단위로 스위칭할 수 있다.

즉 하나의 시뮬레이션에서 다음 두 시간 규모가 동시에 존재한다.

NE555 전기적 스위칭
→ μs~ms 단위

온도 상승과 하강
→ 초 단위

따라서 검증 목적을 두 가지로 나누어야 한다.

장시간 열 거동 확인
.tran 0 60 0 10m startup

이 설정은 온도와 팬 ON/OFF의 장기적인 반복을 보기 위한 것이다.

NE555 PWM 세부 파형 확인

예를 들어:

.tran 0 100m 0 10u startup

와 같이 짧은 구간을 더 작은 시간 간격으로 계산해야 한다.

이렇게 하면 NE555 OUT과 MOSFET GATE의 빠른 상승·하강을 세밀하게 확인할 수 있다.

현재 최종 파형은 온도 제어의 폐루프 동작을 검증한 결과이며, NE555의 정확한 주파수와 듀티비를 검증한 결과로 과장해서는 안 된다.

이 점을 구분하는 것이 포트폴리오의 신뢰성을 높인다.

팬 양단에 약 5V가 걸리고 RPM 신호가 증가한다.

최종 파형에서 팬 ON 구간의 V(RPM)은 약 10V로 나타났다.

여기에서 10V는 실제 팬 단자전압이 아니라 FAN5V.lib에서 RPM을 관찰하기 위해 만든 가상 출력 신호다.

V(RPM)=0V
→ 팬 정지

V(RPM)≈10V
→ 팬 회전 상태

따라서 V(RPM)을 실제 속도계의 측정값처럼 해석하기보다는 팬 모델이 ON 상태에 들어갔음을 보여주는 내부 계측 신호로 사용하였다.

🚨 MOSFET 모델 문법 오류

초기 MOSFET 모델에는 다음 명령이 사용되었다.

.model NMOS_FAN NMOS(
    Vto=2
    Ron=0.05
    Roff=10Meg
)

그러나 Ron, Roff는 일반적인 NMOS 모델에서 그대로 사용하는 파라미터가 아니었다.

LTspice는 다음 경고를 출력하였다.

Ignoring unknown model parameter.

경고가 발생해도 시뮬레이션이 실행될 수 있으므로 처음에는 이를 무시하기 쉬웠다. 하지만 모델의 일부 파라미터가 적용되지 않는다면 의도했던 MOSFET 특성이 반영되지 않는다.

최종적으로 다음과 같이 수정하였다.

.model NMOS_FAN NMOS(
    Level=1
    Vto=2
    Kp=20
    Lambda=0.01
)

이 모델은 실제 특정 MOSFET의 정밀 모델은 아니지만, 게이트전압에 따라 팬 전류를 스위칭하는 기능을 검증하기 위한 단순화된 모델로 사용하였다.

따라서 현재 결과는 특정 상용 MOSFET의 손실이나 온도 특성을 검증한 것이 아니라, 로우사이드 스위칭 기능을 검증한 결과다.

실물 제작 단계에서는 실제 부품을 선정하고 제조사 SPICE 모델 또는 데이터시트를 기반으로 다음 항목을 추가로 검토해야 한다.

📊 최종 파형 분석

최종 시뮬레이션에서 관찰된 신호는 다음 두 개였다.

V(TEMP_MON)
V(RPM)

파형은 초기 약 40℃에서 시작하였다.

이 40℃는 히스테리시스의 하한이 아니라 다음 초기조건 때문이다.

IC=40

첫 번째 구간에서는 팬이 꺼진 상태로 온도가 약 48℃ 이상까지 상승하였다.

상한에 도달하자 V(RPM)이 약 10V로 상승하며 팬이 켜졌다.

온도 약 48.7℃
→ V(RPM) 약 10V

팬이 켜진 구간에서는 냉각항 Pcool=15가 적용되어 온도가 하강하였다.

온도가 약 45.8℃ 부근에 도달하자 V(RPM)이 다시 0V로 내려가 팬이 꺼졌다.

온도 약 45.8℃
→ V(RPM)=0V

팬이 꺼지면 냉각항이 제거되고 발열이 자연방열보다 커지면서 온도가 다시 상승하였다.

↕
약 48.7℃

→ 팬 OFF

→ 팬 ON

특히 같은 47℃에서도 온도 상승 중에는 팬이 꺼져 있고, 온도 하강 중에는 팬이 켜져 있다는 점이 히스테리시스의 동작을 보여준다.

⚠️ 목표 45~50℃와 실제 45.8~48.7℃의 차이

최초 목표는 다음과 같았다.

50℃에서 팬 ON
45℃에서 팬 OFF

그러나 실제 파형은 대략 다음과 같았다.

48.7℃에서 팬 ON
45.8℃에서 팬 OFF

이 차이는 폐루프가 실패했다는 뜻은 아니다.

오히려 전기적 임계값, 비교기 출력, 열 모델의 응답속도가 결합되면서 이상적인 계산과 실제 시뮬레이션 사이에 차이가 발생한 것이다.

가능성이 높은 원인은 다음과 같다.

1. 저항망이 정확히 50℃와 45℃에 맞춰진 값이 아님

현재 값은 다음과 같다.

R6 = 10kΩ
R9 = 3.9kΩ
R5 = 68kΩ

이상적인 비교기 출력 0V와 5V를 가정해도 계산되는 전환점은 약 49.3℃와 44.3℃였다.

즉 저항값 자체가 정확히 50.0℃와 45.0℃로 계산된 조합은 아니었다.

2. LT1016 출력의 실제 HIGH와 LOW가 이상적인 5V와 0V가 아닐 가능성

R5는 LT1016 출력전압을 기준전압 노드에 되먹임한다.

따라서 출력 HIGH가 5V보다 낮거나 LOW가 0V보다 높으면 피드백 전압의 이동 폭이 달라진다.

이는 히스테리시스의 상한과 하한을 동시에 변화시킨다.

현재 최종 파형에는 V(COMP_OUT)을 별도로 저장하지 않았기 때문에 이를 직접 측정해 확정하지는 못했다.

따라서 포트폴리오에는 다음과 같이 표현하는 것이 정확하다.

현재 전환온도 오차는 LT1016 출력전압의 비이상성과 기준전압 저항망의 영향으로 추정하였다. 다만 비교기 출력의 실제 HIGH·LOW 전압을 파형으로 직접 계측하지 않았으므로, 실물 제작 전 추가 검증이 필요하다.

3. 전기적 전환과 열 응답 사이의 지연

LT1016 출력이 바뀐 뒤 실제 냉각항이 활성화되기까지 다음 단계가 존재한다.

LT1016
→ NE555
→ MOSFET
→ FAN5V
→ RPM
→ Pcool

이 신호 전달과 팬 모델의 상태 변화가 완전히 무한히 빠른 것은 아니다.

또한 Pcool=15, Cth=0.5로 냉각 기울기가 크기 때문에 팬 정지 신호가 발생하는 시점 부근에서 온도가 약간 더 내려갈 수 있다.

따라서 실제 파형의 최고점과 최저점은 순수한 비교기 임계값과 완전히 같지 않을 수 있다.

❌ 잘못 판단했던 부분

첫째, 온도가 내려가지 않으면 냉각 세기만 키우면 된다고 생각하였다.

그러나 팬이 꺼져 있다면 냉각계수는 아무런 효과가 없다.

V(RPM)=0
→ Pcool 적용 안 됨

따라서 열 파라미터보다 먼저 팬의 전기적 ON 상태를 확인해야 했다.

둘째, V(RPM)=0이면 모터 모델만 문제라고 생각하였다.

실제로 RPM은 전체 신호 경로의 마지막에 존재한다.

LT1016
→ NE555
→ MOSFET
→ 팬
→ RPM

앞쪽 어느 단계에서든 신호가 끊기면 RPM은 0이 된다.

셋째, 장시간 열 시뮬레이션의 파형만 보고 NE555의 세부 PWM까지 검증했다고 생각할 수 있었다.

하지만 열 응답을 보는 60초 시뮬레이션과 고속 전기 신호를 보는 짧은 시뮬레이션은 분리해야 한다.

넷째, 목표 온도와 실제 파형이 다르면 설계 전체가 실패했다고 생각하였다.

하지만 폐루프 동작과 임계점 정확도는 별개의 평가 항목이다.

폐루프 동작 성공 여부
→ 온도와 팬 상태가 반복적으로 연결되는가?

정확도
→ 실제 상한과 하한이 목표값과 얼마나 일치하는가?

현재 시스템은 폐루프 기능은 성공했으며, 임계점 보정은 후속 개선과제로 남아 있다.

최종 결과는 목표했던 정확한 45~50℃가 아니라 약 45.8~48.7℃였지만, 이 차이를 숨기지 않고 비교기 출력의 비이상성, 저항망의 실제 임계값, 전기적 지연, 열 모델의 동특성으로 나누어 분석하였다.

현재 결과는 완제품이 아니라 시뮬레이션 기반 1차 개념검증이다. 그러나 센서 신호부터 냉각 결과까지 전체 신호와 에너지 흐름을 연결하고, 실패 지점을 단계별로 추적하여 폐루프 동작을 완성했다는 점에서 프로젝트의 핵심 목표는 달성하였다.
